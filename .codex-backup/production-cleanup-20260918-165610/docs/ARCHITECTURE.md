# 前端架构说明

## 分层

```text
页面 pages → 业务 API api → 请求适配 utils/request → Swagger 后端
          ↘ Pinia stores（认证、离线巡检草稿）
```

- 页面不直接拼接后端 URL。
- `src/api` 按业务域拆分。
- `src/types` 统一业务对象和接口返回类型。
- `src/utils/normalize.ts` 兼容后端分页响应差异。
- 演示数据只能由显式演示模式启用。

## 权限边界

- `/get/**`：查询权限。
- `/admin/**`：业务管理与处理权限。
- `/superadmin/**`：用户、角色和系统管理权限。
- 前端负责展示控制，后端必须执行最终鉴权。

## 巡检离线策略

巡检结果、定位和临时图片路径先保存在本地草稿。当前版本在提交时把本地路径交给适配层；附件接口明确后，改为先上传附件并提交附件 ID。
