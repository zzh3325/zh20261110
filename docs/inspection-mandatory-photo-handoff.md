# 巡检必传现场照片与完成条件

更新：2026-11-05。适用 WebApp 项目：daqiao_h5_20260909_codex。

## 1. 本次已实现（WebApp）

- 现场照片只提供拍照入口，每次一张，最多六张，不提供相册选项。HTTP 浏览器的系统拍照选择器仍需实机验证，不能宣称能绝对阻止历史图片或拍摄其他屏幕。
- 新建巡检必须至少拍摄一张；没有照片时页面和 API 封装均拒绝，不调用新增接口。已有其他记录的路径不能冒充新记录照片，新建 photoPaths 仍传空数组。
- 编辑记录至少保留一张已关联照片，或补拍一张待上传照片；将所有已有照片删除且不补拍时拒绝更新。旧无照片记录仍能查看，但再次提交需补拍。
- 仍按当前 Swagger 先保存记录取得 ID，再逐张上传。这一中间过程不提示完成。上传失败保留该 ID 和未成功队列，不再次新增记录。
- 所选照片上传完毕后重新 GET /admin/inspections/{id}，确认该记录至少有一条有效 photoPaths，才显示“提交成功”并约 800ms 后跳转。空数组、无效路径或查询失败均不算完成。
- 记录已保存但照片全部失败后，删除所有待上传照片不能绕过校验；需重新拍摄补传。若服务端保存成功却未返回 ID，锁定重复提交并引导到列表核对，不显示提交成功。
- WebApp 列表的完成判断为“有结果且有已关联照片”；有结果无照片显示“待补照片”，归入“待完善”，不计入完成率。详情无照片时提示编辑补拍。
- 本次不涉及照片水印，不自动删除历史无照片记录，也没有修改后端和 PC 源码。

## 2. 当前后端边界

2026-11-05 查看最新 Swagger：有保存、更新、上传照片、列表和详情接口，但 SafetyInspection 没有独立 completionStatus，且无确认完成接口。

因此 WebApp 已实现自身的提交及显示约束，但不能阻止 PC 或直接 API 调用绕过，也不能在现有后端上把“已保存的无照片记录”物理消除。上传必须先有记录 ID，不能直接让 save 在 photoPaths 为空时一律拒绝，否则会破坏现有流程。

## 3. 发给后端负责人

推荐在现有流程上统一“已保存”和“已完成”概念：

1. POST /admin/inspections/save 保存的是待完成记录，保留现有空 photoPaths 请求和返回 ID；不要立即发完成通知或计入完成统计。
2. POST /admin/inspections/{id}/photos 验证文件确为图片、成功落盘并关联本记录后，再更新完成条件；不能只根据客户端路径声明已有照片。
3. 统一完成条件：结果已填写，且服务器至少关联一张实际有效照片。可派生只读 completionStatus（PENDING_RESULT / PENDING_PHOTOS / COMPLETED）；如业务需存状态，首次有效照片关联和状态变更应事务一致。
4. GET 列表/详情返回权威完成状态，统计、导出、通知都按同一规则处理。没有结果或没有照片不能标记 COMPLETED。
5. PUT /admin/inspections/update 拒绝把已完成记录更新为零照片；补传前保留已有路径，检查照片属于该记录，不接受其他记录路径。历史无照片记录可读取，后续完成操作需补照片。
6. 若后端选择新增显式 POST /admin/inspections/{id}/complete 接口，须先更新 Swagger 和对接前端，不能要求前端调用尚不存在的接口。本次 WebApp 没有虚构调用该接口。
7. 记录保存和照片补传沿用原 ID/凭证幂等逻辑，不能为补图重复建记录；服务端判定照片幂等需独立约定，不可把网络超时当成绝对未写入。

不需要改变固定二维码或点位预设坐标，照片数量校验与二维码核验分别执行。

## 4. 发给 PC 前端负责人

- 新增/编辑/完成巡检时同样要求至少一张有效关联照片，不能只凭 result=正常/异常 就显示已完成。
- 以服务端完成状态为准；在后端状态字段尚未提供的兼容期，至少使用“有结果且 photoPaths 非空”的派生规则。
- 历史无照片、有结果记录显示“待补照片”，提供原记录补图入口；不可自动删除或伪造照片路径。
- 完成率、已完成筛选、导出字段与 WebApp/后端一致，避免同一记录在两端显示不同完成状态。

## 5. 验收

- 新建未拍照片不能提交，网络中没有 save 请求；草稿仍可保存。
- 编辑删除最后一张、且无待上传照片时不能提交，网络中没有 update 请求。
- 上传失败保持待补，重试同 ID，不重复 save；移除失败照片至零张仍不能完成。
- 即使上传接口返回成功，详情查询无照片时也不能显示提交成功。
- 至少一张成功关联且待上传队列处理完毕后才能成功跳转；列表完成率不包括无照片记录。
- 真实手机拍照、权限拒绝、取消拍照、弱网失败和补传需要部署后联调；测试脚本不向正式后台写入数据。
