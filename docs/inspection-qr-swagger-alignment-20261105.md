# WebApp 固定点位巡检：最新后端文档与 Swagger 适配

日期：2026-11-05。项目：daqiao_h5_20260909_codex。

最新补充：现场照片必传至少 1 张，上传后再次查询记录确认关联才提示成功；无照片记录显示“待补照片”，不计完成率。只保留现场拍照入口。后端及 PC 完成状态限制见 `inspection-mandatory-photo-handoff.md`，本次不涉及水印。

依据：用户提供的《固定点位二维码巡检-前端流程(1).md》以及当日读取的 `http://10.20.148.252:9191/v3/api-docs`。本次仅修改 WebApp，未修改 PC、后端或数据库，也未向后端新增测试点位或巡检记录。

## 1. 接口核对

| 请求 | 前端行为与契约 |
| --- | --- |
| GET /admin/inspection-points | 直接接收数组，点位 ID 按字符串，供可选预选使用；WebApp 无增删改管理入口 |
| POST /admin/inspection-points/verify | code 必填，expectedPointId 有值才传；解包 data.point/checkInProof/checkInTime/expiresAt |
| POST /admin/inspections/save | 发送业务字段及核验凭证、点位坐标快照；从 data.id 读取保存后的记录 ID |
| PUT /admin/inspections/update | 保留原有必填字段；不主动提交新的点位、坐标来源、核验时间或凭证来变更快照 |
| GET /admin/inspections?pointId=... | 已接入按点位服务端筛选，未选择时不传 pointId；快速切换不让过期响应覆盖新结果 |
| GET /admin/inspections/{id} | 展示该记录快照，不查当前点位覆盖原名称或坐标 |
| POST /admin/inspections/{id}/photos | multipart 字段 file，一次一张；沿用同一记录 ID 补传 |
| GET /admin/inspections/{id}/photos/{fileName} | 认证获取已关联照片，再显示预览 |

现有请求层继续发送 Authorization: Bearer 登录令牌，并兼容项目旧 token 请求头。点位/巡检列表直接数组和变更接口 {code,message,data} 均由现有解析层支持。安全范围内的数字巡检 ID 保持数字；接口路径使用字符串编码，不损失 ID 精度。

## 2. 此次修改

1. 检查部位：默认带入点位位置，可修改具体检查部位；固定点位 ID 和预设坐标仍只读。
2. 巡检时间：新增页默认跟随手机当前时钟并换算北京时间，每秒同步、显示至分钟，页面重新显示时立即刷新；手动调整日期/时间后停止自动更新，提供“使用当前时间”恢复自动模式。仅明确标记 inspectionTimeUserEdited 的草稿保留手动时间，旧的未标记时间（包括 00:00）不覆盖当前时间。不使用核验时间作为巡检时间；旧记录编辑仍保留原时间。
3. 编辑人员：加载原记录 inspector，更新时不再自动替换为当前登录人。新记录以当前登录人预填，最终身份由服务端确定。
4. 照片重试：收到记录 ID 后立即记住保存状态；成功照片标注“已上传”并从待上传队列移除。失败后点击“重试上传照片”，只对该 ID 上传未成功的照片，不再 POST save 或 PUT update，记录保存后表单业务信息锁定。
5. 防重复：首次请求、照片重试及成功后的 800ms 等待期间均防止连点。若接口报告保存成功却未给记录 ID，锁定新增并提示到列表确认，不再次创建。
6. 筛选：使用后端 pointId 查询参数，保留已知点位选项，支持从单点返回全部；请求序号避免快速切换时旧数据覆盖。
7. 历史兼容：来源空显示“历史坐标”，不自动给未知历史数据补标 WGS84；POINT_PRESET 显示“PC 点位预设，非实时定位”，缺省坐标系按新点位默认 WGS84。

## 3. 保留的业务边界

- 新增巡检页“扫码核验”按钮只请求相机（sourceType:camera），移除二维码相册入口；现场拍摄后本地用 jsQR 识别并调用 verify，核验通过需人员确认。现场照片功能与二维码识别分开，最新规则下现场照片也只提供拍照入口且至少必传一张。
- HTTP 下不使用 getUserMedia 实时视频扫码。系统拍照选择器由浏览器决定，网页不能保证所有设备都绝对禁止历史图片；静态二维码照片、其他屏幕上的码或复制链接仍可能通过核验，去掉相册不能等同于严格到场证明。浏览器 capture 参考：https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture 。
- 页面内扫码保留已填写的项目、检查部位、时间、结论、说明和现场照片；二维码图片仅用于识别，不作为现场照片上传。不打开识别结果中的任意网址，只提取已约定路由的 code 并交给后端校验。

- 没有巡检任务选择、任务派发或任务字段；代码内旧 draft.taskId 只是本地草稿/编辑记录键，不发送为后端任务 ID。
- PC 维护点位和长期二维码。WebApp 不提供二维码管理，不读取手机 GPS，不判断人员与点位距离。
- 可选预选点位依赖同账号同浏览器；无预选明确临时巡检。
- WGS84 固定默认，无坐标系输入；经纬度仍必填且合法，不使用示例坐标替代。服务端错误 message 原样展示。
- 页面内照片重试保留临时照片。离开/刷新后临时图片可能失效，需进入已保存记录重新选择补传；不会持久保存失效 blob URL 当成可恢复照片。
- 单次上传网络超时而服务端已写入时，仅靠浏览器不能判断是否写入，不能宣称照片接口具备严格幂等；若后端要求照片也严格去重，需要进一步约定上传幂等键或文件哈希。当前重试保证不重传已确认成功的照片。
